# Private lifecycle control and evidence (u24)

After `READY`, the explicit disposable runtime exposes one private, bounded
lifecycle endpoint over its **actual** surviving owners. It is the operator
harness's only way to invoke the supported [C9 same-owner restart](restart.md)
and to collect actual source/ledger evidence from a live runtime. It adds no
normal publication, guest RESUME, replacement exporter/FUSE/native owner or
recovery after owner loss. `publication` stays null in every record.

## Endpoint and authority

* The socket is `OwnerDirectory/control.sock`, created exclusively inside the
  private `0700` owner root (an existing name is preserved and refused), mode
  `0600`. There is no guest, network, abstract or reconnect listener. Closing
  removes only that unchanged socket name. Configuration validation refuses an
  owner directory whose socket path would not fit `sockaddr_un` (103 bytes),
  before any owner is created.
* Each connection is authenticated by the kernel peer credentials before any
  request byte is read (Linux `SO_PEERCRED`, FreeBSD `LOCAL_PEERCRED` with the
  checked `xucred` ABI, through the narrow `admin.PeerCredentials` helper). Only
  the daemon's effective UID is accepted. No admin/recovery/audit API is reused.
* `READY` announces `control: {socket, runtime, cut, epoch}`. The runtime UUID
  and cut UUID are generated by the server; the epoch starts at 1. Commands name
  this binding; they never carry Facts, native handles, sources, owners, paths
  or pass/fail values.

## HSC1 framing

Every frame has a 16-byte header: `"HSC1"`, version 1, opcode, two zero bytes,
big-endian uint32 sequence and big-endian uint32 payload length. One connection
carries exactly one request and one reply.

| Opcode | Request payload (fixed length) | Reply |
|---|---|---|
| 1 OBSERVE | runtime UUID (16 bytes) | `{"status":"OBSERVED","sequence":N,"evidence":{...}}` |
| 2 RESTART | runtime UUID, current cut UUID, uint64 epoch (40 bytes) | restart outcome with post-attempt evidence |

Replies use opcode `request|0x80`; frame-level refusals use `0xff`. Unknown
opcodes, wrong lengths (checked before any payload read or allocation), bad
magic/version/reserved bytes, sequence zero and oversized replies refuse.
`{"status":"REFUSED","reason":...}` never claims an effect.

The sequence must be strictly greater than the last accepted sequence. A wrong
runtime UUID or non-monotone sequence refuses without consuming it; any other
accepted command consumes its sequence even if refused later (for example a
stale cut). After a lost reply, the client sends a larger sequence and uses
OBSERVE, which needs only the runtime UUID, to learn the current cut/epoch.

`hfs-controlled-runtime --control SOCKET --operation observe|restart --runtime
UUID --sequence N [--cut UUID --epoch N]` is the matching one-shot client; it
prints the raw reply and exits non-zero on refusal.

## OBSERVE

OBSERVE refreshes **every** actual `Admission` through its pinned guest observer
(a failed or changed observation fences that Admission exactly as any refresh
does; nothing is retried) and captures, from the current actual owners:

* supervisor issuance stage, process, controller, endpoint, live check and the
  bounded s24 exporter diagnostics snapshot;
* per Admission: refresh error, fence, boot, provider nonce, kernel build,
  physical inventory hash and every domain's phase/revision/fence;
* service state, journal incarnation/owner/generation/configuration and a fresh
  complete view source (`Through`, `Applied`, visibility, state hash/bytes)
  taken on the service worker within the signed `SourceBytes`;
* each provider's protected ledger digest (the digest C9 compares), inode and
  size under its execution mutex;
* the view controller's protected ledger digest, size, whether the live state
  equals those protected bytes, and inert counts;
* the live C8 ledger index (controller, endpoint, high-water, cells, classes,
  workspace, terminal/HELLO witnesses, guest high-water) and its full digest,
  read under the transport mutex so the cut equals the last protected transition.

Each section reports its own error text (truncated to 512 bytes) instead of
inventing a value. `complete` only means every section was captured without
error and the lifecycle is not FENCED; it is not an acceptance flag. Closed,
suspended, absent or partial owners are reported as such. An external
invocation/reply oracle must correlate these records.

## RESTART

RESTART requires the exact current runtime, cut and epoch and the SERVING stage.
It then consumes the single attempt (a fresh cut and incremented epoch are
issued whatever happens) and calls the real `Supervisor.SuspendEndpoint`,
`Restart.Reopen` and `Restart.Activate` on the retained Producer/Transport:

* success switches the lifecycle's current owners to the reopened
  service/Facts/providers/controller/Producer/Transport (stage RESTARTED); the
  native shell dispatch was switched and the same C exporter resumed by
  Activate;
* failure (step `suspend`, `reopen` or `activate`) leaves the supervisor fenced,
  blocks admission on every reachable service and retains all original and
  nonnil partial owners (listed in `partial_owners`) until runtime exit. There
  is no rollback, exporter resume or owner deletion. Fencing closes the native
  management channel, so the runtime then ends as on any owner loss, retaining
  files, mount and VM resources.

The outcome plus its post-attempt evidence is protected in the exclusive owner
file `control-restart.json` before the reply is written. A later RESTART always
refuses. Without a native shell-switch primitive the operation refuses before
any effect.

## Bounds and funding

A single worker accepts and serves connections strictly serially, so OBSERVE and
RESTART never overlap. Each connection has a 5 s I/O deadline for its request
and reply; OBSERVE has 30 s and RESTART 90 s (the C9 grant itself expires after
60 s). Requests are at most 56 bytes; replies at most 128 KiB.

`fundRuntime` reserves a separate admission lease for this endpoint before any
owner exists: one worker, one connection and
`1 MiB + C8 peak (128 KiB + 8 MiB + 8 MiB) + 2 × LedgerBytes + 3 × SourceBytes`.
The host budget check includes it and `runtime-budget.json` records it under
`Control`, with the 128 KiB `control-restart.json` disk bound. The lease is
returned only after the endpoint's worker joined. Closing the endpoint stops
accepting and joins the bounded in-flight command (its reply and protected
outcome are not truncated by an owner-loss shutdown); parent cancellation still
propagates into that command.

## Evidence boundary

`lifecycle_test.go` drives the shared command driver through actual proposal,
signed handoff, real supervised C strong startup/backend/ledger and HELLO to
READY, then uses the real endpoint and client: actual OBSERVE evidence is
compared with the live owners; a real C9 restart pauses/binds/resumes the actual
C exporter over HSR1, reopens all owners from their files and serves a further
original scope through the restored transport. Negative tests cover foreign
and unavailable peer credentials, malformed/oversized/short frames, a stalled
partial frame at the deadline, wrong runtime, repeated/lower sequences, stale
cut/epoch, repeated restart, inconsistent guest physical state (truthful fenced
evidence and a FENCED suspend) and a refused native switch (FENCED activate with
retained partial owners). The kernel peer credentials (when a test says so),
native mount/INIT/fd syscalls, FUSE shell dispatch switch and observed guest
physical state are explicitly substituted OS boundaries. Native FreeBSD
execution, actual lost-reply response exposure (v24) and the real 9p base gate
(zq3) remain unrun and unclaimed.
