# lib9p FreeBSD unnamed-socket fix: native verification (task m34, 2026-11-08)

Native verification of commit `2875d3d` (merged with test follow-up `303a031`)
in disposable guest **hfs-test0** (FreeBSD 15.1-RELEASE), with fdescfs
`-o nodup` on `/dev/fd`. This is test and component evidence; it does not
qualify the real daemon, READY or the 9p base gate (zq3). The final xz3 rebuild
must include this fix.

## Result

- **Whole `controlledruntime` package natively: PASS.** 84 tests pass and none
  fail (guard: exit 0, 99.8 s, peak RSS 356 MiB). The two skips are by design:
  `TestDescriptorExecNativeUnsupported` skips on a supported `/dev/fd`, and
  `TestPortableFixtureCannotMintNativeAuthority` is a Linux-only boundary.
  The 10 restart/driver tests that failed in [l34](../20261108-l34-native/)
  on `!_recovery_socket()` now pass.
- **`tools/integration/lib9p/native-verify.sh`: PASS** with the guest's `cc`:
  `production_api_test`, `backend_test`, `ledger_test` and `supervisor_test`.
  `supervisor_test` admits a real FreeBSD socketpair and refuses bound and
  datagram sockets. Its "Preserved adapter ledger/fsync failure evidence" line
  comes from the test's own deliberate fsync-failure case. The first attempt
  stopped at `backend_test` because the frozen `fixtures.h` input was not
  staged ([record](lib9p-native-verify-r1-missing-fixtures.txt)). The second
  attempt staged the header generated by `tests/fixtures.py` (hash in
  [artifacts.sha256](artifacts.sha256)), as `verify.sh` does on Linux.
